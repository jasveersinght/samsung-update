=== SLIDE 2 ===
BASELINE MANIPULATION TESTING IN KITCHEN WORLD
The initial phase of the project focused on validating the existing
VLM-TAMP pipeline
and the Kitchen World simulation environment. Multiple pick-and-place tasks were performed to verify that the robot could successfully detect, plan, grasp, transport, and place different objects.
Test Cases Performed:
Scissor pick-and-place operation
Cabbage retrieval from refrigerator
Chicken leg retrieval from refrigerator
Bottle pick-and-place operation
Objective:
To establish a reliable baseline before integrating
dynamic world-state awareness and replanning capabilities.

=== SLIDE 7 ===
CUSTOM FOUR-ROOM WORLD MODEL FOR TIAGO BOT TESTING
Video 5
:- A custom world model was developed consisting of
four separate rooms
to test the navigation, object detection, and pick-and-place capabilities of the Tiago robot. Two of the rooms contain
tables positioned at the corners
, with various tools and objects placed on them for performing object detection and pick-and-place operations. The remaining two rooms contain
human models acting as dynamic obstacles
, allowing the system to test whether the Tiago robot can navigate safely without colliding with people occupying the space. Additionally, each room has been designed with a
single entry and exit point
, creating controlled navigation paths and increasing the complexity of movement planning. This custom environment enables comprehensive testing of the Tiago robot's perception, navigation, obstacle avoidance, and manipulation capabilities.

=== SLIDE 12 ===
PROBLEMS DISCOVERED DURING INTEGRATION
1. Physical vs Semantic Objects
PyBullet
Physical Body ≠ Scene Graph Semantic Object
Some objects exist physically in the simulation but may not yet have a corresponding semantic representation in the Scene Graph.
2. Environment Changes During Execution
PLAN CREATED
↓
ROBOT EXECUTES
↓
ENVIRONMENT CHANGES
↓
OLD PLAN MAY BECOME INVALID
3. Immediate Replanning Can Be Unsafe
Current Plan A
↓
Robot Executing Action
↓
Event Detected
↓
New Plan Generated
The new plan should not blindly replace the currently executing plan. The system requires
safe execution and replanning synchronization
.
4. Planner Failure ≠ Perception Failure
An object may be successfully represented in the Scene Graph, but the planner may still fail to generate a valid plan.
5. Environment Object States
Some objects have additional states beyond their position.
Examples:
Microwave
CLOSED → OPEN
Cupboard
CLOSED → OPEN
Braiser
Lid
CLOSED → OPEN
These state changes can affect the accessibility of objects.
Status:
IDENTIFIED AND UNDER INVESTIGATION
